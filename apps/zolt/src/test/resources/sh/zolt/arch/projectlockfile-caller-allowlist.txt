# path|reason
# Files allowed to CALL sh.zolt.lockfile.ProjectLockfile.in. The seam turns a lock ROOT into a path;
# this list says who is allowed to decide which directory is the lock root. Design §4.5: a command
# started inside a workspace member has two roots, and the member-local `zolt.lock` is observationally
# irrelevant, so a core build/test/package operation RECEIVES the authoritative path — as a
# ProjectBuildContext or an explicit lockfilePath parameter — and never derives one.
#
# Three kinds of entry are legitimate, and the reason must say which:
#   * command boundary     - decides the (projectRoot, lockRoot) pair once, for everything downstream
#   * workspace root       - the workspace owns its one authoritative lock
#   * standalone entry     - a standalone project directory IS its own lock root

# --- command boundary -------------------------------------------------------------------------
apps/zolt/src/main/java/sh/zolt/cli/command/ProjectCommandContext.java|command boundary; loads the (projectRoot, lockRoot, lockfilePath, memberPath) pair once and hands it down
apps/zolt/src/main/java/sh/zolt/cli/command/CommandProjectLockfile.java|command boundary; resolves a started directory to the workspace root that owns the lock
apps/zolt/src/main/java/sh/zolt/cli/command/WorkspaceCommandToolchainState.java|command boundary; fingerprints the workspace root's lock for the toolchain state a workspace command carries
apps/zolt/src/main/java/sh/zolt/cli/command/dependency/ManifestMutationScope.java|command boundary; establishes the lock root a manifest mutation writes back through
apps/zolt/src/main/java/sh/zolt/cli/command/dependency/DependencyUpdateScopeResolver.java|command boundary; reads the discovered workspace root's lock to scope an update
apps/zolt/src/main/java/sh/zolt/cli/command/insight/TreeCommand.java|command boundary; reads the discovered root's lock, which discovery already resolved to the workspace root

# --- designated owners ------------------------------------------------------------------------
modules/zolt-model/src/main/java/sh/zolt/lockfile/ProjectBuildContext.java|designated owner; the standalone factory is where a standalone project declares itself its own lock root
modules/zolt-workspace/src/main/java/sh/zolt/workspace/service/Workspace.java|workspace root; the one place the workspace lane names its authoritative lock, handed to members as a context
modules/zolt-workspace/src/main/java/sh/zolt/workspace/resolve/WorkspaceResolveService.java|workspace root; resolve writes the workspace's one authoritative lock
modules/zolt-workspace/src/main/java/sh/zolt/workspace/resolve/WorkspaceLockFreshnessService.java|workspace root; lock currency is a property of the workspace root's lock
modules/zolt-resolve/src/main/java/sh/zolt/resolve/lockfile/persistence/ResolveLockfilePersistence.java|designated owner; the resolve writer names the file it persists for the directory it was told to resolve
modules/zolt-plan/src/main/java/sh/zolt/plan/BuildPlanRequest.java|designated owner; models lockfilePath as a field and derives only in its standalone factory and its member comparison
modules/zolt-plan/src/main/java/sh/zolt/plan/BuildPlan.java|designated owner; models lockfilePath as a field and derives only for the standalone default and its member comparison
